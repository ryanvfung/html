## 4. What A got wrong — or overreached

25. **F4's TypeScript speculation contradicts the plan's own constraints.** A suggests "the missing 13th is `typescript` (plausible given `vite.config.ts`/`playwright.config.ts` want typechecking)". The plan contains no typecheck step anywhere — no `tsc` script (lines 93–101), no `typecheck` in `verify` (line 100), and both configs are shipped verbatim (lines 769–785, 1138–1146). 26. **F24 (favicon console flake) likely doesn't reproduce.** A lists as a risk that the console-error test (lines 1163–1169) will catch a missing `/favicon.ico` 404. Playwright runs headless Chromium, which typically does not fetch favicons for pages without an icon link, so the request — and its console error — often never occurs. The finding is correctly parked in LOW confidence, but the proposed fix (ship a favicon or filter the URL) is addressing a probable non-issue; it should be resolved empirically at Task 21 rather than carried as a plan defect.
27. **F2's `@import "./_tokens.scss"` fix has an unverified extension caveat.** A proposes adding `@import "./_tokens.scss";` to the Tailwind entry on the grounds that "the token file is plain CSS, so the Tailwind CLI can inline it." The content is indeed CSS-compatible, but the file is named `.scss`, and CSS pipelines commonly resolve imports by extension — Tailwind v4's bundler may require a `.css` file or a Sass-aware resolver. The zero-doubt version of A's own fix is to have Task 20 consume a `.css`-named copy (or assert the import compiles as part of the probe). A asserted the mechanism as settled without being able to execute it — the same standard A applies to B's static findings.
