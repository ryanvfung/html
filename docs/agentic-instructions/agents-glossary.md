# agents-glossary.md — persistent terminology

- Purpose: a shared vocabulary so design, planning, and review stay consistent across sessions. `design` and `plan-writing` must add new terms here when they coin or disambiguate one.
- Format: each entry is `<term>` — one-line definition. Keep it small; the glossary is a reference, not a spec.
- When to update: whenever a skill introduces a term that could be read two ways, or renames an existing concept. Dedupe against existing entries before adding.
- Out of scope: don't list project-specific API names, class names, or variable names unless they carry a non-obvious meaning that affects design decisions.
