# agents-propose-guard.md — PROPOSE-vs-IMPACT rule + hook deployment
- PROPOSE-vs-IMPACT: propose/design/spec → output proposal only, do not implement. Implementation permitted ONLY when explicit action directive accompanies propose intent (verbs: execute/implement/fix/build/run/do/go ahead/start/apply/make/create + compound forms). Presence of propose-class keyword alone blocks mutation; propose + action verb allows mutation after proposal delivered first. If execution intended but no verb (e.g., only "propose"), ask for confirmation.
- HOOK DEPLOY: the propose-guard hook ships with this template at `<REPO_DIR>/.hooks/propose-guard.js`; its registration ships at `<REPO_DIR>/.root/.opencode/opencode.json` and lands at workspace-root `.opencode/opencode.json` after the sync (with `{{REPO_DIR}}` substituted to the actual repo dir by `copy-to-root.ps1`). Activation depends on the agent framework loading the config (unverified until loaded) — not via .md rule. The static rule above applies by instruction regardless.
